# Arch Linux packaging

## Dependency compatibility (#292)

Build XerahS and its recorded submodules as one revision. Do not clone ImageEditor
or Omacut at independent branch heads, and do not use `git submodule update --remote`.
The editor API can change between parent commits; the reported missing gradient
properties were caused by mixing incompatible revisions.

The repository-owned `build/linux/aur/xerahs-git/PKGBUILD` initializes submodules with
`--checkout` and checks the complete recursive dependency state before compilation.
A missing or advanced dependency fails early with an actionable error, rather than
failing later inside the image effect importer.

For an existing development checkout, preserve your local dependency changes before
running `git submodule update --init --recursive --checkout`. Build packages in a
clean checkout. If an AUR helper cached the older community recipe that clones editor
repositories independently, choose a clean build after updating the recipe, or use
the repository-owned recipe described here. The public AUR listing is maintained
separately; a commit to this repository does not update that listing.

Validation: `bash build/tests/verify-submodules.sh` exercises pinned, independently
advanced and uninitialized dependencies using disposable local Git repositories.

## Repository-owned package (#284)

The canonical recipe is [PKGBUILD](../../build/linux/aur/xerahs-git/PKGBUILD), with
[.SRCINFO](../../build/linux/aur/xerahs-git/.SRCINFO) generated by `makepkg --printsrcinfo`.
It builds `KovaForge/XerahS`'s `develop` branch and the exact dependency revisions
recorded there, including OmaSnap. This is a development package, not the upstream
ShareX stable release channel.

On Arch, install the standard `base-devel` prerequisite, copy `PKGBUILD` into an
empty build directory, then run `makepkg --syncdeps`. The normal recipe requires
no environment overrides or separate ImageEditor/Omacut clones. Review the recipe
before installing build dependencies or the resulting package. To build the current
local repository instead, run `bash build/linux/package-aur.sh`; only committed
source is included, and packages are copied to `dist/aur/`. Local sources are
trusted build inputs; when the selected source is a partial clone, Git may fetch
its missing objects during the first package build.

The `Arch package` GitHub workflow checks generated metadata and runs the actual
package build as an unprivileged user in a fresh Arch container. It uploads the
resulting package as a CI artifact; it does not publish to AUR.

Maintainer publishing checklist:

1. Confirm co-maintainer access with the current public AUR package owner.
2. Copy `PKGBUILD` into that package's AUR Git checkout, regenerate `.SRCINFO`, and
   build in a clean Arch environment.
3. Review the source URL, recursive submodule pins and package payload, then publish
   using the maintainer's AUR SSH credentials.

Public AUR ownership/publishing remains external to `KovaForge/XerahS`. Until that
transfer and publication happen, `yay -S xerahs-git` may still use the community
recipe; the checked-in recipe and CI artifact are the fork's validated sources.

## Build-server shutdown and plugin publishing

Arch packaging always publishes plugins serially because they share project outputs.
The general Linux packager bounds each `dotnet build-server shutdown` request to
15 seconds, with a five-second termination grace period. A failed or stalled
shutdown client emits a warning and packaging
continues; this maintenance operation must not block completed compiler output.
The timeout targets only the shutdown client, not unrelated task processes.

`bash build/tests/shutdown-build-servers.sh` covers successful, failed and stalled
shutdown clients without touching real SDK servers. This fixes the first clean
Arch CI run, which finished its app and plugins in about three minutes and then
waited at server shutdown until the CI job expired.
